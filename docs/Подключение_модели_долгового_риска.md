# Подключение Excel-модели «Оценка проекта и долгового риска»

Модуль оптимизации получает стоимость и эффект проектов напрямую из заполненного
шаблона финансовой модели, а долговой риск переводится в ограничение финансирования.

## Что извлекается (лист «3. Исх проект данные и риски»)
- **Стоимость (cost)** = суммарный CAPEX по годам проекта (стр. 12), напр. 700+80+60+0 = 840.
- **Эффект (effect)** = NPV проекта (стр. 15), напр. 172,84 (ставка дисконтирования —
  отраслевой WACC листа 5, уже учтён в NPV).
- Дополнительно: IRR, NPV и IRR при стрессе, ряды и минимумы DSCR (Кпз) и ICR,
  денежные потоки. Строки находятся по тексту показателя — устойчиво к смещению шаблона.

## Долговой риск → предел финансирования (credit_limit)
Норматив DSCR — 1,3 (постановление Минэкономики РБ № 158). Если минимальный DSCR
проекта не ниже норматива, ограничение не накладывается. Иначе финансируемая сумма
ограничивается запасом обслуживания долга:

    credit_limit = CAPEX · (DSCR_min / норматив)

Пример: при DSCR_min = 0,694 и CAPEX 840 → credit_limit = 840·0,694/1,3 ≈ 448,36. В
оптимизаторе это даёт cap = min(стоимость, credit_limit): даже при достаточном бюджете
проект финансируется не более чем на 448,36 (≈53 %) — «в границах кредитоспособности».
Норматив (`dscr_norm`) настраивается; эвристика прозрачна и при необходимости уточняется.

## Программные компоненты
- `app/services/debt_risk_model.py` — `parse_debt_risk_model(path) → ProjectFinance`,
  `credit_limit_from_finance(pf, dscr_norm)`, `project_finance_to_opt(pf, name, …) → OptProject`.
- `app/services/etl.py::load_project_finance(db, org, path)` — сохраняет CAPEX →
  `Project.capex`, NPV → `DigitalProjectItem.npv`, предел → `Project.credit_limit`.
- Модель данных: добавлен столбец `Project.credit_limit` (миграция a036cc892a7e).
- `candidate_projects_from_db` теперь передаёт `credit_limit` в кандидата оптимизации.
- API: `POST /optimization/projects/import-model` (multipart: файл .xlsx + organization_name;
  доступ — офис цифровизации, госорган) разбирает модель и сохраняет проект.
- Интерфейс: на странице «Оптимизация» — загрузка модели; стоимость, эффект и кредитный
  предел подставляются в таблицу проектов автоматически.

## Тесты
`tests/test_debt_risk_model.py` (7): разбор реального файла (CAPEX 840, NPV 172,84,
IRR 0,270, DSCR_min 0,694, ICR_min 6,371, стресс-значения), расчёт credit_limit,
конвертация в OptProject, цикл ETL→кандидат и API (загрузка модели, разграничение ролей,
оптимизация по данным БД с учётом кредитного предела).

## Замечание
Шаблон рассчитан на один проект; для портфеля модель заполняется и загружается по каждой
организации. Стоимость — суммарный CAPEX за горизонт; при необходимости (учёт только
первоначальных вложений) логику легко настроить.
