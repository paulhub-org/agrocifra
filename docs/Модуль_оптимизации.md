# Финансово-математический модуль оптимального уровня затрат на цифровизацию

Реализует пункт дорожной карты «финансово-математический модуль … (комбинированный
подход: оптимизация эффекта в границах кредитоспособности и долгового риска)». Это
отдельный исследовательский модуль; в нумерации спринтов разработки Спринт 6 — это
«Развертывание и тестирование», Спринт 7 — «Финализация».

## Постановка (MILP, решатель PuLP/CBC)
По каждой организации (проекту) одновременно определяются:
- бинарный выбор xᵢ ∈ {0,1} — финансировать ли проект;
- непрерывный объём средств fᵢ — сколько выделить.

**Целевая функция:** max Σ (эффектᵢ / стоимостьᵢ)·fᵢ + w·Σ_{оценкаᵢ ≥ порога} xᵢ —
максимизация суммарного эффекта плюс (с весом w) охват организаций, превысивших порог
эффективности/зрелости.

**Ограничения:**
- fᵢ ≤ capᵢ·xᵢ, где capᵢ = min(стоимостьᵢ, кредитный пределᵢ) — **граница
  кредитоспособности / долгового риска**;
- бинарный проект: fᵢ ≥ стоимостьᵢ·xᵢ (всё-или-ничего);
- масштабируемый проект: fᵢ ≥ min_shareᵢ·стоимостьᵢ·xᵢ (мин. жизнеспособная доля);
- Σ fᵢ ≤ бюджет.

Эффект масштабируется долей финансирования: вклад = (эффектᵢ/стоимостьᵢ)·fᵢ.

## Программные компоненты
- `app/services/optimization.py` — `OptProject`, `optimize_allocation(...)`,
  `candidate_projects_from_db(...)` (стоимость = Project.capex, эффект = Σ(ЧДД+ROV)
  элементов портфеля, оценка = последняя КЭц или зрелость).
- `app/schemas/optimization.py` — `ProjectIn`, `OptimizationRequest`.
- `app/api/optimization.py` — эндпоинты (доступ: офис цифровизации, госорган):
  - `POST /optimization/run` — запуск (явные `projects` либо данные из БД) → сохраняется
    `OptimizationRun`, возвращается распределение;
  - `GET /optimization/runs`, `GET /optimization/runs/{id}` — история и результат.
- Интерфейс: `frontend/src/components/Optimization.jsx` — таблица проектов (стоимость,
  эффект, тип, КЭц/зрелость, кредитный предел), параметры (бюджет, порог, вес охвата),
  диаграмма распределения и таблица решений. Пункт меню «Оптимизация».

## Тесты
`tests/test_optimization.py` (13): корректность «рюкзака», соблюдение бюджета, бинарный
режим «всё-или-ничего», минимальная доля, кредитный предел (включая нежизнеспособность
при min_share·cost > предел), вес охвата, пустые/нулевые случаи, валидация, а также
API (запуск, разграничение ролей, 422 без проектов, история).
