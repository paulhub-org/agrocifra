# Развёртывание и тестирование «АгроЦифра» (Спринт 6)

Документ описывает развёртывание системы на одном сервере (VPS) с помощью Docker
Compose, проверку работоспособности, резервное копирование, нагрузочное и сквозное
тестирование, а также непрерывную интеграцию (CI).

## 1. Состав развёртывания
Три контейнера, объединённые во внутреннюю сеть Compose:
- **db** — PostgreSQL 15 (данные в именованном томе `pgdata`);
- **backend** — FastAPI/Gunicorn (Uvicorn-воркеры), при старте применяет миграции и
  при необходимости создаёт демо-пользователей;
- **frontend** — Nginx: отдаёт собранный интерфейс (React/Vite) и проксирует `/api/*`
  на backend. Публичная точка входа — порт **80**.

Веб-интерфейс обращается к API по относительному пути `/api`, поэтому отдельная
настройка адреса backend и CORS в типовой схеме не требуется (один источник).

## 2. Предварительные требования
- Docker Engine 24+ и Docker Compose v2 на сервере (Linux).
- Открытый порт 80 (при необходимости — TLS-терминатор/реверс-прокси перед Nginx).

## 3. Первый запуск
```bash
git clone <репозиторий> agrocifra && cd agrocifra
cp .env.example .env
# отредактируйте .env: задайте POSTGRES_PASSWORD и SECRET_KEY (openssl rand -hex 32)
docker compose up -d --build
```
При старте backend автоматически выполняет `alembic upgrade head`; при `SEED_DEMO=1`
создаются демо-пользователи **org / region / office / gov** (пароли `*123`).
После первичной инициализации в продакшене установите `SEED_DEMO=0` и смените пароли.

## 4. Проверка работоспособности (smoke-test)
```bash
docker compose ps                      # все сервисы healthy
curl -s http://localhost/api/health    # {"status":"ok"}
curl -s http://localhost/api/version   # {"app":"АгроЦифра","version":"0.1.0"}
```
Откройте `http://СЕРВЕР/` — должен загрузиться веб-интерфейс; вход под демо-учётной
записью (например, `office` / `office123`).

## 5. Управление
```bash
docker compose logs -f backend         # журналы
docker compose restart backend         # перезапуск сервиса
docker compose down                    # остановка (том БД сохраняется)
docker compose pull && docker compose up -d --build   # обновление
```
Применить новые миграции после обновления кода: происходит автоматически при
перезапуске backend (entrypoint), либо вручную:
`docker compose exec backend alembic upgrade head`.

## 6. Резервное копирование и восстановление
```bash
./scripts/backup.sh                    # дамп в ./backups/agrocifra_<дата>.sql.gz (+ ротация)
./scripts/restore.sh backups/agrocifra_YYYYmmdd_HHMMSS.sql.gz
```
Планирование (cron, ежедневно в 02:30):
```
30 2 * * *  cd /opt/agrocifra && ./scripts/backup.sh >> backups/backup.log 2>&1
```
Переменные: `BACKUP_DIR`, `RETENTION_DAYS` (по умолчанию 14 дней).

## 7. Тестирование
**Сквозное (E2E) и модульное** — выполняется в CI и локально:
```bash
cd backend && pip install -e ".[dev]"
pytest -q                              # включает tests/test_e2e.py (полная цепочка API)
```
E2E-сценарий (`tests/test_e2e.py`) проходит цепочку: вход → оценка зрелости и
эффективности → сводка и выгрузка отчёта (Excel) → импорт Excel-модели долгового риска
→ оптимизация по данным БД и по явному портфелю. Браузерный E2E в данной среде не
применяется; проверка ведётся на уровне API (реальные HTTP-вызовы к приложению).

**Нагрузочное (Locust):**
```bash
pip install locust
locust -f loadtest/locustfile.py --host http://localhost:8000          # веб-интерфейс :8089
# безголовый прогон:
locust -f loadtest/locustfile.py --host http://localhost:8000 \
       --headless -u 50 -r 5 -t 2m --csv loadtest/report
```
Для доступа через Nginx укажите `--host https://ВАШ_ДОМЕН/api`. Сценарий моделирует
вход и взвешенную смесь запросов: `/health`, `/reports/summary`, `/optimization/run`,
`/optimization/runs`.

## 8. Непрерывная интеграция (GitHub Actions)
Workflow `.github/workflows/ci.yml` на push/PR выполняет:
1. **backend** — `ruff` (линт), `alembic upgrade head` на сервисе PostgreSQL (проверка
   миграций), `pytest` с покрытием (включая E2E);
2. **frontend** — установка зависимостей и сборка Vite;
3. **docker** — сборка образов backend и frontend и валидация `docker compose config`.

## 9. Замечания по безопасности (продакшен)
- Смените `SECRET_KEY` и пароль БД; установите `SEED_DEMO=0` и удалите/смените демо-учётные записи.
- Порты БД и backend по умолчанию не публикуются наружу (доступ только внутри сети
  Compose); открывайте их (закомментированные `ports`) лишь для администрирования.
- Рекомендуется поставить перед Nginx TLS-терминатор (например, Caddy/Traefik или
  внешний reverse-proxy) и ограничить `allow_origins` доменом клиента, если API
  публикуется отдельно.
